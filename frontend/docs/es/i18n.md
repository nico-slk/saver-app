# Internacionalización (i18n)

[English](../en/i18n.md) · [← Volver](../../README.md)

Idiomas: **español (`es`, por defecto)** e **inglés (`en`)**. Librerías: `i18next`, `react-i18next` e `i18next-browser-languagedetector`.

## Cómo se elige el idioma

1. Idioma guardado en el navegador (`localStorage` → `saver.lang`), si el usuario lo cambió.
2. Idioma del navegador (`es-AR` → `es`, `en-US` → `en`).
3. Español como respaldo.

Al iniciar sesión **manda el idioma guardado en el perfil** (`user.locale`). Si el usuario cambia el idioma con sesión iniciada, también se guarda en el backend (`PATCH /api/me`), así lo sigue en otros dispositivos.

## Archivos

```
src/i18n/
├── index.ts          # configuración, SUPPORTED_LANGUAGES, INTL_LOCALE
└── locales/
    ├── es.json
    └── en.json
```

Claves agrupadas por sección: `nav.*`, `auth.*`, `settings.*`, `errors.*`… **Ambos archivos deben tener exactamente las mismas claves.**

## Uso

```tsx
const { t } = useTranslation();
<h1>{t('dashboard.greeting', { name: user.displayName })}</h1>
```

## Errores del backend

El backend devuelve códigos (`auth.email_taken`); se traducen con `translateError(t, error)` buscando `errors.auth.email_taken`. Al agregar un código nuevo en el backend, agregarlo en `es.json` y `en.json`.

## Números, monedas y fechas

Usar siempre los helpers de `lib/format.ts`, que aplican el formato del idioma activo:

| Función | `es` | `en` |
|---|---|---|
| `formatMoney(1234.5, 'ARS')` | `$ 1.234,50` | `ARS 1,234.50` |
| `formatDate('2026-10-25')` | `25 oct 2026` | `Oct 25, 2026` |
| `formatPercent(0.153)` | `15,3%` | `15.3%` |

Las fechas sin hora (`AAAA-MM-DD`) se interpretan como fecha local (`parseDate`), para no mostrar el día anterior en zonas horarias con desfase negativo como Argentina.

## Agregar un idioma

1. Crear `src/i18n/locales/<lng>.json` copiando `es.json` y traduciendo.
2. Registrarlo en `src/i18n/index.ts` (`resources`, `SUPPORTED_LANGUAGES`, `INTL_LOCALE`).
3. Agregar su nombre en `languages.<lng>` de todos los archivos.
4. En el backend, admitirlo en la validación de `locale` (`UserDtos`, `AuthDtos`).
